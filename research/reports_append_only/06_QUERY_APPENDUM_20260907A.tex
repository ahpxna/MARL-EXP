\section*{71. Diagnosis: the response estimand, not the gate}
The protocol measured
\[Q^{(1)}_j(a)\;=\;r_{\text{outcome}}\bigl(s,\ a_j,\ a_{-j}^{\text{baseline}}\bigr),\]
the reward of a \emph{single} environment step after a clone-state intervention. In RWARE with five agents, one step almost never completes a delivery, so $Q^{(1)}_j(\cdot)$ is constant in $a$ and $\max_a Q-\min_a Q=0$ by construction. The oracle already implemented the continuation return
\[Q^{(h,\rho)}_j(a)=\sum_{t=0}^{h-1}\gamma^{t}\,r_{\text{outcome}}(s_t)\ \Big|\ \operatorname{do}(A_j=a)\ \text{at}\ t=0,\ \text{then}\ \rho,\]
including early termination on \texttt{done} and the assignment \texttt{reward = float(discounted)} --- but the transfer runner constructed \texttt{CloneStateJointOracle} without \texttt{horizon}, so $h=1$ always.

\section*{72. Code change: the estimand is now selectable and self-declaring}
\texttt{run\_external\_query\_transfer} gains \texttt{--horizon}, \texttt{--discount}, \texttt{--continuation-policy}. Defaults $h=1$, $\gamma=1$ reproduce protocol v4 byte for byte, so \textbf{no existing artifact is invalidated}. For $h>1$ the artifact rewrites its own declaration: \texttt{protocol\_version} becomes \texttt{external\_query\_transfer\_v5\_continuation\_return\_frozen\_policy}, \texttt{response\_estimand} becomes \texttt{Q\_continuation\_h\{h\}\_gamma\{g\}}, and the definition string states that the result is \emph{not} comparable with any \texttt{Q\_one\_step} artifact. $\rho$ must be explicit and frozen; the oracle refuses $h>1$ without it.

\oldclaim{Switching the estimand from the one-step $Q$ to a continuation return will make the targets non-degenerate.} \textbf{It does not.} The plumbing is confirmed correct --- the protocol version, estimand name, horizon and discount all propagate --- and the measured outcome is identical at $h=1$, $4$ and $8$. \eclass{DEMOTED: proposed direction, measured insufficient}

\textbf{Narrowed root cause.} The blocker is the \emph{competence} of $\rho$, not the horizon. RWARE's \texttt{fixed\_continuation\_policy} returns action $0$ (NOOP) for every agent unconditionally, so under $\rho=$\texttt{noop} the continuation contributes exactly zero and $Q^{(h,\rho)}$ collapses onto $Q^{(1)}$ identically. The declared reference policy \texttt{forward} (each agent takes its first non-idle valid action) does move the agents and still yields no delivery within $h\le8$; it is deterministic in the state and carries no hidden counter, so the estimand does not depend on enumeration order, but it is not task-competent and is recorded in the artifact as never constituting a policy-performance claim.

\section*{74. What remains, and the non-claim}
Three hypotheses survive, in increasing cost:
\begin{enumerate}
\item A task-competent frozen $\rho$ (move toward the requested shelf, then toward a goal) makes $Q^{(h,\rho)}$ non-degenerate. The adapter exposes \texttt{raw\_env.agents[i].x/.y/.carrying\_shelf} and \texttt{grid\_size}, so this is writable, but RWARE requires turn-then-advance control and it must be tested in the external runtime before it enters the ledger.
\item The reward is too sparse for any short horizon and the estimand must change kind, not length.
\item The state distribution is the blocker: reset-plus-warmup states are far from delivery. The \texttt{delivery\_opportunity} positive control produced $28$ evaluable cells against $0$ for reset states --- but its own \texttt{evidence\_class} is \textsf{DEVELOPMENT\_POSITIVE\_CONTROL}, so it diagnoses plumbing and establishes nothing about transfer.
\end{enumerate}
\claimbox{\textbf{Non-claim.} No transfer performance result exists for this chain at any horizon. \texttt{benchmark\_readiness} remains \textsf{EXTERNAL\_PRIMITIVE\_FRAMEWORK\_READY\_FULL\_RELATIONAL\_QUERY\_BENCHMARK\_NOT\_READY}. Five methods and four queries remain \textsf{BLOCKED\_NA} for missing capabilities, unchanged.}
