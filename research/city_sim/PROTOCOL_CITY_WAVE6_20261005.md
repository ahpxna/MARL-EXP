## W6-1 DCA: a published generic observation adapter (DC-Ada) in place of TSI's physical adapter, at matched budget

**Comparator:** DC-Ada (Alqithami, IEEE Access 2026). Accept/reject random search with common random numbers over a compact observation transform of a FROZEN policy, as ported in `scripts/CITY_dcada_tune.py` (04/10).
- **Transform:** affine o' = o·exp(s) + b on RL-H's 7 inputs (θ ∈ R^14, θ0 = 0 = identity), via `--light-obs affine:FILE` (`CITY_eval4.LightRLX`).
- **Fleet side:** unchanged TSI hybrid service (same per-light forecaster `tsi_20261005/cmodel/c2/n2_k<t>.pt`, c2 tables). Only the light-side adapter differs from TSI-2.
- **Tuning (per light t4–t8, TUNE 660–663, development fleet L11_s13):**
  - R once per TUNE seed (4 rollouts);
  - then 4 rounds; round r uses TUNE seed 660 + r for the base rollout and M = 9 Gaussian candidates θ + σε (σ = 0.3), under the same seed (CRN);
  - the best candidate is accepted iff its return exceeds the base return (τ = 0).
- **Budget:** 4 + 4 × 10 = **44 rollouts per light, equal to TSI-2's tuning (10 grid points × 4 + R × 4).**
- **Return** (higher is better) = −J, with J = Δfuel_agent % + 4·[ΔTL_agent + 0.25]₊ + 4·[ΔTL_city]₊ + 4·[ΔTL_human]₊ against R on the same seed. This is a scalar form of TSI-2's selection rule.
- **Confirmation (760–779; t4–t8 × s213–s513):** arms R, TSI2 (C-118's per-light (A, B), unchanged), DCA (per-light tuned θ).
- **Decisions (one-sided 95 %):**
  - (a) DCA meets every M3 limit vs R (yes / no).
  - (b) TSI2 − DCA, agent fuel and agent TL:
    - "TSI better" iff both uppers ≤ 0 and at least one < 0;
    - "DCA better" iff both lowers ≥ 0 and at least one > 0;
    - else "no ordering".
  - (c) TSI2 vs R on this third fresh panel meets every M3 limit (a replication of P1 at α 0.05, same checkpoints).
- **Checks:**
  - KW1-1: an affine file with θ = 0 reproduces the HYB rows (smoke seed, bit-identical endpoints).
  - KW1-2: the tuning log holds exactly 44 rollouts per light.

## W6-3 H5: constrained fleet objective (Lagrangian on agent time loss)

**Hypothesis (opt H5):** a constrained fleet objective meets the agent-TL margin.
- **Recipe:** F1-B scratch (identical) with one change, applied through a wrapper that patches `CITY_fleet_v10.dense_cost`. The time term max(0, 1 − v/v_lim) is weighted by (1 + λ).
- **λ update** after every episode: λ ← max(0, λ + 0.5 · (TL_agent(ep) − TL_agent^R(seed, k) + 0.25)), with λ0 = 0.
- TL_agent^R(seed, k) is the R row of that TRAIN seed under RL-H:k, from 8 R episodes per light run at the job start (counted, not hidden).
- Episode agent TL comes from the run's tripinfo (agents = the fleet's members).
- **Pairs as H4:** `--mode h5`.
- **Confirmation and decision as H4** (F1H5 vs R; descriptive F1H5 − F1B).

## W6-4 LCD: a learned committed-duration light (DHCP-type structure: predictable, publishes exact timing)

**Light:**
- At the onset of each yellow, the duration of the green that follows is chosen and committed. The mechanism is N8's CDC (`CITY_eval_n8.py`: setPhaseDuration(max(1, d − spent)); SPaT `spat_cdc`, exact by construction; check KN8-1).
- The choice is made by a shared DQN (MLP 64-64) over D = {5, 10, 15, 20, 25, 30, 40, 50, 60} s.
- **Features:** vehicles and halting on the lanes of the green to start and of the other green, /20.

**Training:**
- SUMO cars only; TRAIN seeds 0–7 cycled; 120 episodes.
- ε from 1 to 0.05 over the first 80 episodes; replay 200 k; batch 256; Adam 1e-3; Huber loss; γ = 0.9 per decision; target net copied every episode.
- **Reward of a decision:** −(halting vehicle-seconds on all lanes of that light from this commit to the light's next commit) / 100.
- **Light seeds:** j0, j1. Script `scripts/CITY_lcd.py`.

**DEV gate (600–611; registered as the N8 condition):** the LCD light alone (SUMO cars) has city TL upper < +0.5 against RL-H k0 / k1 (two-sample over light seeds, paired traffic).

**If the gate passes — confirmation (760–779):**
- arms LCDF (LCD j0 / j1 + R10 s213–s513 with exact SPaT) against R (RL-H t4–t8, no SPaT);
- lights differ between the arms, so the bootstrap resamples light seeds separately per arm, with fleets and traffic paired.
- **Report:** agent fuel, city / agent / human TL, plus LCD alone vs RL-H alone.
- **Decision:** "a learned predictable light with exact SPaT meets every M3 limit vs R" (yes / no).

**If the gate fails:** reported as a failed DEV gate; no confirmation is run.

## W6-5 M2-L: the compatibility test with BOTH populations learned

**Cast:**
- L0 = RL-H t4–t8 (learned).
- F0 = the four F1-B fleets (learned under L0 with the c2 provider).
- **L1** (learned), chosen at **stage 0** on DEV 600–605 with SUMO cars, among the frozen families RL-J (t0–t3), SIM-delay, SIM-halt and ALT-halt (k0–k3). The family with the lowest mean city TL is chosen.
  - It is labelled an **upgrade** iff its city TL minus RL-H's has a crossed upper < 0 (light seeds resampled separately per family, traffic paired).
  - Otherwise it is labelled a **learned-light replacement (not an upgrade)**.

**L1 forecast table:** 8 TRAIN episodes per L1 light, with L11_s13 and no SPaT (σ\*), logged by `CITY_n2_collect.py --featlog`, fitted by `CITY_spat_forecast.fit` (open-loop table; the c2 augmentation is applied by `make_spat_c2`).

**Arms (760–779):**
- under L0: R0 and F0c (F0 with L0's table, q 0.1);
- under L1: R1; F0n (naive: the table each F0 fleet was trained with, i.e. L0's t<k> table, used under L1); F0r (L1's own refitted table).

**Endpoints:**
- B0 = F0c − R0, B1n = F0n − R1, B1r = F0r − R1 (agent fuel %, agent / human / city TL);
- DiD = B1 − B0 (lights unpaired between L0 and L1; fleets and traffic paired).

**Decisions (one-sided 95 %):**
- **LOSS** iff the DiD fuel lower bound > 0 for the naive arm;
- **HARM** iff the B1n fuel lower bound > 0 or the B1n agent-TL lower bound > +0.5;
- **INFORMATION UPDATE SUFFICES** iff B1r meets every M3 limit vs R1.

# Wave 6 pre-run audit amendment — 2026-10-05

Written by the continuing audit session. Jobs 052–055 were moved pending→hold before they started; 051 was allowed to finish unchanged. Its report and all tuning outcomes were read before this amendment. No confirmation output of 052–055 exists at amendment time. Existing protocols, traffic splits, policy seeds, budgets, candidate grids and historical verdicts are retained except for the explicit corrections below.

1. **H5 reference horizon bug:** trainer ends at 3600s (smoke 300s), old reference evaluator ends at 5400s (smoke 600s). New `CITY_eval_h5_reference.py` records exactly 3600/300s, matching the trainer and agent assignment. Both use tripinfo including partial unfinished trips at that horizon. Store horizon/light identity, assert finite dual inputs, and log unfinished agents. This is a horizon-limited training surrogate, not an exact Lagrangian of completed-trip evaluation at 5400s. H4 recipe unchanged. End-to-end smoke with one training episode passed; not scientific evidence.
2. **SP3 validity and exactness:** the multi-green branch counted a response as valid despite underlying `valid=False`. More seriously, a yellow program phase can retain green for an individual movement. Old code forecast a future onset for that already-green movement. An independent realized-trace smoke found 206/2269 scored answers wrong. Publish exact upcoming onsets only when the queried movement is not currently green and the next green serves it. Treat truly always-green only if every program phase serves the link. Other cases return unavailable. Updated smoke: 1988 scored, 0 mismatches, 7 censored; 2373 valid calls including always-green. Historical spider attempt 1/2 files stay untouched; their multi-green timing semantics are limited by the shared provider bug.
3. **Self-check gates:** SP3 compares every nontrivial published timing against observed link green onset; any mismatch stops the run. LCD requires positive scored count, zero timing mismatches, correct traffic membership. Previously shell checks only printed FAIL. New shell runners fail on pipeline/subprocess errors.
4. **Reports:** versioned `CITY_w6_report_v2.py` uses strict COMPLETE/duplicate/seed-set/finite-metric/count validation. Missing teleport/unfinished fields are errors, not zeros. LCD human-only comparisons request city TL only, avoiding meaningless NaN agent metrics. Original 051 reporter and result remain unchanged.
5. **M2-L inference:** DEV-selected family is a provisional candidate, not a confirmed upgrade. Report baseline-fleet feasibility and L1-vs-L0 city TL on the existing fresh confirmation rows (no extra simulations). HARM's two alternative endpoints use Bonferroni one-sided .025 each. Other registered gates remain unchanged. Forecast fitting requires all eight TRAIN traces (one in smoke).
6. **DC-Ada fidelity:** 051 is a DC-Ada-style affine-search adaptation, not published-algorithm reproduction. The original author code uses per-robot residual nets, truncated CRN rollouts and a default noise scale .05; local port uses a shared 14-coordinate affine transform, full rollouts and .3. Its soft objective is not equivalent to TSI's feasibility-first selector. TSI also sees extra speed-bin counts. Keep and report 051, including 0/20 accepted rounds and no Pareto ordering; do not use it to claim a fair algorithmic win over DC-Ada.
7. **LCD naming:** learned committed duration is a structural predictable-signal reference, not a reproduction of DHCP. DHCP uses hierarchical DDPG cycle splitting with distinct straight/turn movements; this script is a nonhierarchical DQN selecting durations.
8. **N4 metadata:** after 051 completed, future N4 runs now record model/table/fleet/controller hashes. Cached historical rows are not backfilled. Retrospective freeze records remain retrospective.

No new performance branch added. Return the already-authorized jobs to the sequential spool once these checks are complete. Full traffic/seed confirmation, not smoke performance, determines their verdicts.
